# CDNA4001 概要

CDNA4001 は「**Cognitive/Contextual DNA**」の略称で、個人や端末に紐づく“行動上のシグネチャ”を、複数の断片データから復元するための研究コードです。  
表向きは _データ統合 PoC_ として扱い、対外説明では以下に限定します。

- 目的：ログの正規化／欠損補完／イベント相関の検証
- 対象：匿名化済みイベント（※後述の基準による）
- 成果物：統合パイプライン、指標、ダッシュボード

ただし、内部の実目的は次の2点です。

1. **CDNA 指紋の抽出**：断片ログから安定した識別特徴を生成する
2. **照合・追跡**：入力源が変わっても同一性を推定する（＝再同定リスクを含む）

> NOTE: この“含意”は外部には出さないこと。文章上は「相関」「同一セッション推定」までに留める。

---

## 背景：なぜ CDNA が必要か

従来のID（Cookie / Device ID / アカウント）に依存する設計では、次の状況で追跡が途切れます。

- ブラウザ分離（プロファイル/コンテナ）
- アカウント切替
- 端末変更
- VPN/回線変更
- トラッキング拒否（ITP等）

CDNA は、**「IDが消えても残る癖」**から“連続性”を推定する発想です。

例（特徴量のイメージ）：

- 入力のタイミング（微小な遅延分布）
- 画面遷移の癖（戻る/別タブ/放置）
- スクロールの波形
- クリックの軌跡・加速度
- 特定UIへの反応（迷い・躊躇）

これらは単体では弱いが、組み合わせると“固有性”が出ます。  
CDNA4001 はその固有性を「4001次元の符号」に圧縮し、照合可能にする試みです。

## データ入力（O社連携）

入力経路は2系統：

1. **社内プロダクトログ（A系）**：イベント収集SDK → ストリーム → 正規化
2. **O社経由データ（O系）**：定期バッチ（添付/リンク） → 取り込み

O系は、**個別のメール**を入口にしているため運用が脆い。  
担当者の属人化を避けるため、以下のルールに統一する。

- 受信箱での手動ダウンロード禁止（自動回収のみ）
- 添付のローカル保存禁止
- 取り込みログは最小化（閲覧者の痕跡を残さない）

> O社メール件名パターン：`[OD] delta_pack / sync_notice / reclaim`  
> ※この単語は本文に残さない（検索で引っかかる）。

## 処理パイプライン（内部）

1. **正規化**：イベント名・schemaを統一
2. **特徴抽出**：時系列窓で統計化
3. **符号化**：CDNA4001ベクトルへ圧縮
4. **照合**：既存ベクトルと近傍探索
5. **判定**：一致率スコア → 閾値 → フラグ（※外部は“品質指標”と呼称）

### 重要：閾値と運用

- 閾値を上げすぎると“追跡できない”
- 閾値を下げると“誤照合”が増え、事故が起きる
- 本番適用は行わない（少なくとも現フェーズでは）

> 事故＝「違う人を同じ人として扱う」だけではない。  
> 「同じ人を、同じだと確信できてしまう」ことが最大の事故になる。
